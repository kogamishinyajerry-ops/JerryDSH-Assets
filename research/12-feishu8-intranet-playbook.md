# 12 · 飞书 8.0 对标研究：DSH 内网离线复刻可行性 + 硬件方案

**日期**：2026-09-15（飞书 8.0 发布当日调研）
**问题**：飞书 8.0 升级了什么？DSH 能否在内网离线环境实现类似效果？哪些复刻/哪些不复刻？哪些自己造/哪些用开源？内网要飞书级协作至少什么硬件？
**方法**：发布会全量公开报道（中青报/央广网/新华财经/智东西/潮新闻 5 源交叉）+ 本仓 01-11 研究结论映射。

---

## 一、飞书 8.0 到底升级了什么（事实层）

发布主体三个产品，一个共同主题：**Agent 成为平台一等公民**。

### 1.1 飞书 8.0 for Agent（平台重构）

| 升级点 | 细节 |
|---|---|
| Agent 进群 | 搜索名字即可拉 Agent 进群，像拉同事；多 Agent 群内互相协作 |
| Agent 用产品 | 撰写文档、操作多维表格、安排日程待办、参与会议、查云盘/妙记、发起审批，"人能做的 Agent 几乎都能做" |
| 飞书 CLI | 功能点 **247 → 767**，调用成功率 **78% → 95%**，速度 **+39%**（2026-03 上线以来迭代） |
| 文档内 Agent | 文档右侧边栏唤出，@Agent 答疑、改内容、取数 |
| 权限治理 | **Agent 权限始终与使用者一致**，员工看不到的 Agent 也看不到 |
| 用量管理 | 按部门/个人设 Token 上限、高消耗场景定向管控、用量 API 开放 |

### 1.2 豆包工作（个人 Agent，原生融入飞书）

- 与飞书共用账号体系、双端互通、完整上下文
- 产物：Word/Excel/PPT/网页/应用生成 + **局部修改**（指哪改哪）
- 操作电脑/浏览器/本地文件；**云电脑**机制云端持续运行；多 Agent 并行拆任务
- 长期记忆（记住 PPT 偏好等）；技能 + 连接器（Gamma、博查等）

### 1.3 豆包工作伙伴（团队智能体，国内首个，原"飞书 aily" 8/14 更名）

- **独立身份、权限、记忆**，像同事一样常驻群聊
- 企业统一配置权限/能力/用量，全员共用一个伙伴，无需各自设置
- **主动工作**：识别项目问题自主分析修复、跨职级权限主动向上请求、把讨论沉淀成卡片
- **团队共享记忆**：记住群聊/文档/会议内容，积累复用团队技能经验

### 1.4 周边

多维表格（一句话搭业务系统直接上线、AI 分析榜单第一、AI 友好数据库人机共管）、飞书项目（AI 节点 + CLI 对外开放）、智能会议纪要、AI 会议耳机（安克联合研发）、画板 Agent 信息图。

### 1.5 一句话本质

梁汝波原话点题：**智能体、模型、协作环境三者必须紧密融合**。飞书 8.0 = 协作环境（数据+工具+权限）全面向 Agent 开放，豆包工作 = Agent runtime，模型 = 豆包/火山。内网复刻问题因此等价于：**这三层各自用什么替代、接缝在哪。**

## 二、DSH 底盘对照（本仓 01-11 研究结论）

| 飞书 8.0 要素 | DSH 现状（基线 0.1.1-rc.2） | 判定 |
|---|---|---|
| Agent runtime（豆包工作） | agent loop 核心（09）、工具五段流水线、会话持久化/投影/compaction（07）、LLM 适配层（10，可接内网本地模型） | **有，且是强项** |
| CLI 功能点 767 | MCP 客户端（08 §六）：外部工具注册为原生工具 `mcp__server__tool`，命名空间隔离 | **机制等价，功能点数量取决于自建工具层** |
| 多 Agent 协作 | Subagent 体系（11）：spawn/fork、可继续 Activation、Agent Teams（任务 DAG + 共享 mailbox，实验性） | **有，agent-agent 维度完整** |
| 人-Agent 群聊 | 无 IM 层。Agent Teams 是 agent 间协议，不是人机群聊 | **缺，需外挂 IM** |
| 身份/权限继承 | 08 结论：插件/MCP 同 UID 全权限，**无身份级权限模型**；审批/沙箱管的是"模型调用能力"不是"人" | **缺，且是结构性缺口** |
| 团队共享记忆 | honcho-memory 插件可自部署 Honcho 后端（03），或自建 | **半成品，需建设** |
| 主动工作 | 生态有推送/定时插件（04，chicheng-push/cron 实测通过） | **有雏形** |
| 用量管理 | token 计量在（10），但无企业面板 | **有数据无面板** |
| 办公产品本体（文档/表格/会议/审批） | 无，DSH 是 harness 不是协作平台 | **缺，本就不该 DSH 做** |

**核心结论**：DSH 能胜任内网版"豆包工作"（Agent runtime 层），MCP 机制就是内网版"飞书 CLI"。但飞书 8.0 的另一半「协作环境 + 治理」不在 DSH 职责范围，靠开源拼装 + 薄胶水层。**这条路成立，但 DSH 是发动机，不是整车。**

## 三、复刻可行性矩阵

### 3.1 能复刻（开源 + 薄胶水）

| 飞书能力 | 内网替代栈 | DSH 接缝 | 成本判断 |
|---|---|---|---|
| Agent 进群、@Agent 干活 | **Rocket.Chat**（自托管 IM，bot API 成熟） | bot 收 @ 消息 → 起 DSH 会话 → 回帖；群上下文注入 prompt | 低，桥接层 ~几百行 |
| CLI 767 功能点 | **自建 MCP 工具层**：把下述每个产品的 REST API 封装成 MCP server | DSH MCP 客户端原生消费（08 §六） | 中，每个工具薄，累计是主工程 |
| 文档协同 | **OnlyOffice Docs**（Community 版免费，Word/Excel/PPT 实时协同 + Conversion API） | MCP 工具：读/写/转文档；产物自动回传 OnlyOffice 打开 | 低-中 |
| 多维表格 | **NocoDB / APITable**（开源多维表格，REST API + webhook） | MCP 工具：建表/读写/视图/表单；AI 分析= agent 读表→pandas→写回 | 低 |
| 日历/待办 | Rocket.Chat 自带或 Radicale CalDAV | MCP 工具 | 低 |
| 会议 | **Jitsi Meet** 自托管（录制/白板/共享屏幕） | 录音文件自动流入纪要管线 | 低 |
| 智能会议纪要（妙记） | **已有资产**：COMAC-内网智能纪要智能体（ASR→说话人分离→摘要→渲染），ASR 用 FunASR/Whisper 离线 | 接 Jitsi 录音即闭环 | **近零，强化即可** |
| 产物生成（Word/Excel/PPT/网页） | 内网开源模型 + python-docx/openpyxl/python-pptx 管线（已有大量本地经验） | DSH 本职 | 低 |
| 画板 Agent 信息图 | **Excalidraw** 自托管（场景格式是简单 JSON，对 Agent 极友好） | MCP 工具：生成 .excalidraw 文件投群 | 低 |
| 知识库 | Outline / MediaWiki 自托管 | MCP 工具检索写入 | 低 |
| 文件盘 | Seafile（社区版，同步性能好）或 Nextcloud | MCP 工具 | 低 |
| 云电脑持续运行 | 内网常驻服务器跑 DSH daemon + cron 调度（04 已验证定时推送） | daemon 化部署 | 低 |
| LLM 网关/用量管控 | **one-api / new-api**（开源 LLM 网关：多用户配额、用量统计、渠道管控） | 内网模型服务前置网关；用量 API 直接有 | 近零 |

### 3.2 复刻不了 / 不值得复刻（诚实清单）

| 飞书能力 | 为什么复刻不了 | 内网对策 |
|---|---|---|
| **权限继承**（员工看不到的 Agent 也看不到） | 背后是十年组织架构账号体系 + 全链路 ACL。DSH 是同 UID 全权限（08 §七），补齐=重写半个飞书 | **简化信任模型**：服务账号制 + 按数据密级分区挂载 + 全量审计日志。7 人团队够用，这是内网小团队对飞书的真正降维差异点，别硬追 |
| 千万行多维表格 + 一句话搭系统直接上线 | 数千人团队多年工程打磨 | NocoDB 覆盖 60-70% 场景；"搭系统"降级为"agent 建表+视图+表单脚本化" |
| 豆包工作产物质量 | 产物上限=模型上限。内网 72B 级 vs 豆包旗舰 | 链路 100% 复刻，质量预期打 7-8 折；按任务分级路由模型 |
| 移动端全端体验 | App 工程量巨大，内网还发不了 App Store | 桌面浏览器优先，内网 WiFi + 移动网页版兜底 |
| AI 会议耳机 | 硬件产品线 | 不做，共享电脑音频进 FunASR |
| 飞书级产品打磨 | 不解释 | 接受"工程队自用工具"的毛坯感 |

### 3.3 造轮子决策（什么自己写，什么坚决不写）

**自己写（薄、贴身、有战略杠杆）**：

1. **MCP 工具层**（P0，对应飞书 CLI）：OnlyOffice/NocoDB/Jitsi/Seafile/Outline 各封装一个 MCP server。单片都薄（REST API 包装），合计就是内网版"767 功能点"。这是整个方案的操作系统接口层，不写它一切免谈。
2. **IM-bot 桥**（P0）：Rocket.Chat bot ↔ DSH 会话。@唤起、群上下文注入、结果回帖、文件互传。把"拉 Agent 进群"做真。
3. **团队记忆层**（P1）：基于 DSH 会话日志 + 向量库（Qdrant/Milvus，bge-m3 本地 embedding）。飞书伙伴的核心壁垒就是"记住团队上下文"，开源没有贴身现成品，这块自研最值钱。
4. **主动补位策略**（P2）：什么话题该接、什么该沉淀成任务卡。策略是自己的，底层 cron + inbox 投递 DSH 已有。
5. **权限简化模型**（P1）：服务账号 + 密级分区 + 审计导出。薄但内网合规必需。

**坚决不写（用开源成熟方案）**：

| 需求 | 开源方案 | 理由 |
|---|---|---|
| IM 本体 | Rocket.Chat / Mattermost | 自托管生态最成熟，bot API 完整 |
| 文档协同 | OnlyOffice | 免费版够用，API 全 |
| 多维表格 | NocoDB / APITable | APITable 本身就是国产开源多维表格 |
| 会议 | Jitsi Meet | 自托管事实标准 |
| LLM 网关/配额 | one-api / new-api | 用量管控原生支持，造它毫无意义 |
| ASR | FunASR / SenseVoice | 中文场景强于 Whisper，且已有管线 |
| 向量库 | Qdrant / Milvus | 本体永远不造 |
| 文件盘 | Seafile | 国产、同步性能好 |
| 低代码 | Appsmith / ToolJet | 真要"搭系统"时再用，别急着上 |

## 四、内网硬件配置评估

负载四类：LLM 推理（大头）、约 8-10 个自托管服务、embedding/向量检索、ASR。团队 6-7 人 + agent 后台任务。

### 4.1 分档方案

| 档位 | 配置 | 模型能力 | 体验预估 | 预算量级 |
|---|---|---|---|---|
| **A 验证档** | 1×RTX 4090 24G + 单路 EPYC/至强 128G 内存 + 2T NVMe | Qwen3-32B AWQ / GLM-4-Air 级，vLLM 并发 2-3 路 | 能跑通全链路，流式延迟和并发是瓶颈，70 分 | **5-7 万** |
| **B 推荐档** | 2×RTX 4090（48G）或 1×RTX PRO 6000 96G + 256G 内存 + 4T NVMe + 16T HDD RAID5 | Qwen3-72B AWQ / GLM-4.5-Air 级，vLLM 并发 5-8 路，全团队流畅 | 主力体验档，85 分 | **12-18 万** |
| **C 舒服档** | H20 96G ×1-2 + 服务节点分离（64G 内存 x86 跑全家桶） | 72B 全精度吞吐好，并发 10+ 路，agent 多路并行无感 | 接近豆包响应感 | **25-40 万** |
| **D 信创档** | Atlas 800I A2（8×910B）或 300I Duo 推理卡 + MindIE | 32B-72B 可跑，生态走 CANN/MindIE | 商飞体系若要求信创采购走这条，预算上浮 | 10 万起 / 整机百万级 |

### 4.2 B 档参考清单（推荐起点）

- **推理/一体节点 ×1**：2U 服务器，EPYC 9004 单路 + 8 通道 256G DDR5 + 2×RTX 4090 + 2×2T NVMe（系统/模型）+ 4×16T HDD（RAID5，文件盘/会议录像/备份）
- **万兆交换机 ×1**（模型加载、大文件、会议流）
- **UPS 3kVA** + 标准机柜位
- 软件全栈（docker compose）：vLLM + one-api + Rocket.Chat + OnlyOffice + NocoDB + Jitsi + Seafile + Outline + Qdrant + DSH daemon，全部离线镜像包导入（复用 U 盘/离线包搬运流程）

### 4.3 模型栈（全离线开源）

| 用途 | 选型 |
|---|---|
| 主力对话/Agent | Qwen3-72B AWQ 或 GLM-4.5-Air（4bit） |
| 轻量/高并发 | Qwen3-30B-A3B（MoE，激活 3B，并发友好） |
| embedding | bge-m3 或 Qwen3-Embedding（本地） |
| ASR | FunASR Paraformer / SenseVoice（中文+标点+时间戳） |
| 视觉（可选） | Qwen3-VL 32B |

### 4.4 容量估算（为什么 B 档够）

- 72B 4bit 权重 ~40G 显存，KV cache 留 ~8G/卡：单流 20-30 tok/s，并发 5 路可用。7 人团队同时在线打字高峰约 3-4 路并发 + agent 后台 2-3 路，恰好覆盖
- 服务全家桶内存 32-64G，256G 内存余量充足
- 存储：会议录像+文档+文件盘按 5 年 10T 估，RAID5 32T 可用容量富余

## 五、落地路线（P0/P1/P2）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0 打地基**（2-4 周） | 推理节点到位 + vLLM + one-api 网关 + DSH daemon 化 + Rocket.Chat + **IM-bot 桥**（@agent 能干活） | 群里 @它 "把这份表格按科室汇总发我"，端到端跑通 |
| **P1 协作面**（4-8 周） | OnlyOffice + NocoDB + Seafile + **MCP 工具层**（文档/表格/文件读写）+ 权限分区 + 审计 | agent 能读协同文档、写多维表格、产物自动进文件盘 |
| **P2 智能面**（8-12 周） | 团队记忆层 + 主动补位调度 + Jitsi 纪要管线打通 + 用量面板 | 伙伴能在群里主动提醒风险、会后自动出纪要 |

**P0 验收场景是对标"豆包工作伙伴"的最小真身**：一个有名字、进群、被 @ 就干活、干活用工具（MCP）、干完回帖的常驻 Agent。

## 六、锐利结论

1. **方向成立**：飞书 8.0 证明"协作环境 × Agent × 模型"融合是正解，内网复刻的本质是**开源拼协作环境 + DSH 当 Agent runtime + 内网开源模型**。三者接缝全部是 REST/MCP 标准接口，无黑盒。
2. **DSH 定位要认清**：它是发动机不是整车。整车 = 开源全家桶 + 自写胶水（MCP 工具层 + bot 桥 + 记忆层，合计估 3-5 k 行自研代码，其余全是配置）。
3. **最大的坑是权限**：飞书"Agent 权限=使用者权限"复刻不了也不该复刻。用"服务账号 + 密级分区 + 审计"的简化模型，这在 7 人内网团队是更合理的信任设计，不是妥协。
4. **硬件别一步到位**：先 A 档验证全链路（5-7 万），体验瓶颈实测后再上 B 档（12-18 万）。若体系有信创硬要求，直接跳 D 档询价 Atlas。
5. **已有资产别浪费**：纪要智能体（妙记替代）、OpenCode 离线包流程（装机方法）、DSH 研究结论（runtime 选型依据）全部直接复用。
