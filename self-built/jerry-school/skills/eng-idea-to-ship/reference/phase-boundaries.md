# 阶段边界决策树（eng-idea-to-ship 参考）

**阶段（phase）**＝会话内的一段工作：拷问、实现、QA。边界＝两个阶段之间的空隙——这个决策只属于那里；阶段中间没有决策可做：继续，或把剩余工作拆给子代理。中途压缩会让 agent 丢线。

五个选项：

| 选项 | 做什么 |
|---|---|
| **Continue** | 留在本会话。零成本，零损失。 |
| **新会话（clear）** | 清空上下文，从零开始。 |
| **Handoff** | 写可携带的 markdown 文档，在任何地方喂给新会话。 |
| **子代理** | 把任务送进它自己的上下文窗口，拿报告回来。 |
| **压缩（compact）** | 压缩本上下文，用摘要起新会话。 |

## 决策树（自上而下，第一个"是"获胜）

**1. 本会话能继续吗？** 两条任一为真就是能：下一阶段需要本阶段作为**一手来源**；或剩余 **smart zone**（~150k token）够装下一阶段。拷问 → 实现是标准的"能"：实现要的是推理的*原文*不是摘要。Continue 什么都不花什么都不丢——先排除它。

**2. 上下文对接下来无关吗？** 本会话的一切（探索、决策、死胡同）都可弃？→ **新会话**。棋盘上最便宜的棋。清掉相关的上下文代价是单向的：丢掉*为什么*，读 diff 读不回来。

**3. 需要交接吗？** Handoff 很窄，只在这些时候：换**新 harness**、换**新目录/仓库**、交给**同事**、阶段中间**分叉支线任务**。这个清单就是全部条款——handoff 买的是*可携带性*，没有东西在旅行就不需要它。

**4. 任务能 AFK 干吗？** 范围紧到无人值守可跑（自动审查是标准案例）→ **子代理**，本会话原封不动。

**5. 否则，压缩。** 相关上下文、同 harness、同目录、你还得在场——树落在这里，而且常落在这里。压缩时给一句指引（"接下来要 QA 这块"）让摘要留住下一阶段需要的东西。

**压缩是默认项，不是第一反应。** 它垫底是因为上面四问都更便宜或更精准。从它开始的人得到的常是一个对被摘要拍扁的决策"自信地错"的新会话。

## 一手/二手来源

Continue 以外的每个动作都把**一手来源**（实际发生的会话）变成**二手来源**（它的摘要）。交易形状永远一样：

| 来源 | 信息 | 噪音 | 回旋余地 |
|---|---|---|---|
| 一手（Continue） | 全 | 多 | 小 |
| 二手（压缩/handoff） | 有损 | 少 | 大 |

这就是问题 1 排第一的原因：只有"留下"的代价高于所得时才付有损的价。

这些都是判断题：同一条边界两天可以走两条路。价值在于**按序**问、**在边界上**问，而不是在活干到一半时问。

### Handoff 文档写法

- 总结当前会话，让新 agent 能接着干；写到 OS 临时目录，不进工作区。
- 含"建议技能"节：点名下一个 agent 该加载哪些技能。
- 不复述其他产物（spec/ADR/issue/commit/diff）已捕获的内容——按路径/URL 引用。
- 脱敏一切敏感信息。
