# AI Coding 双语词典（dsh-school 参考）

蒸馏自 aihero.dev AI Coding Dictionary（免费内容，~70 词条）中与"理解 agent 在干什么"最相关的部分，中文释义按原文忠实压缩，个别条目补 DSH 语境。按主题分组。

## 基础：模型与推理

**Model（模型）**：一组训练出来的参数文件。它只会一件事：文本进、文本出。不能读文件、跑命令、记住上一轮——那些都是 harness 给的。

**Training（训练）**：调整参数直到模型善于预测文本的过程。训练完就冻结——你使用时它不学习。

**Inference（推理）**：训练后用冻结参数生成输出的过程。你每次对话都是推理。

**Next-token prediction（下一 token 预测）**：模型的基本动作——对"下一个 token"产出概率分布，采样一个，重复。不是"查数据库"，是"接龙"。

**Token**：模型读写的原子单位。约等于词但不精确：常见词一个 token，生僻长词拆几个。经验值 1 token ≈ 0.75 个英文词；代码更不可预测（标识符、hash、base64 每词多 token）。窗口大小、成本、延迟全按 token 计。

**Parametric knowledge（参数知识）**：训练压进参数的"知识"。细节被挤压：罕见事实会糊。是流利的来源，也是编造的来源。对应物是 contextual knowledge（装进上下文的知识）。

**Knowledge cutoff（知识截止）**：训练数据的时间边界。之后的世界它一无所知——除非你装进上下文。

**Non-determinism（非确定性）**：同样输入可能得到不同输出。采样本身带随机（永远选最大概率会复读）。代码一行没变，两次回答不同，正常。

**Hallucination（幻觉）**：自信地错。两种：**事实性**幻觉（编造世界事实——不存在的函数、假 API 签名）← 参数知识缺口，修法是把正确知识装进上下文；**忠实性**幻觉（偏离已装进上下文的指令/事实）← 注意力衰减，修法是 clear/compact。

**Sycophancy（谄媚）**：自信地附和。训练塑造了"人类喜欢被同意"的倾向。表现：被质疑就反转正确答案、夸烂方案。对抗：要求它先挑错再评价。

**Effort（推理力度）**：模型回答前思考量的旋钮。思考以 token 生成、按输出计费。调高更准更慢更贵。

## 机制：harness 与上下文

**Harness（具装）**：围着模型把它变成 agent 的一切——工具、system prompt、上下文管理、权限、钩子。同一个模型装进不同 harness 表现不同（DSH 与别家跑同一个模型行为不同，变量是 harness 不是模型）。agent 循环（模型提案→harness 执行→喂回结果→重复）由 harness 驱动。诊断行为差异时先怀疑 harness。

**Agent**：被 harness 装配起来（模型+工具+system prompt+上下文窗口）与用户轮替交互的整体。你真正对话的那个单位。

**System prompt（系统提示）**：harness 前置在每次请求上的常驻指令：它是谁、怎么行为、有哪些工具。coding harness 里它很大（数万 token，每轮都付钱）。你自己的常驻指令（AGENTS.md 等）搭在它旁边。

**Context window（上下文窗口）**：模型每次请求看到的**全部**东西——一个有限的 token 序列：system prompt + 对话至今 + 每个工具结果。在序列里它就能用；不在它就不知道存在——不是你的代码库、不是你昨天编辑的文件、不是三个会话前的指令。窗口外的任何东西都要靠工具调用搬进来。有限意味着会满：每轮都在追加，长会话最终触发 compaction 或 clearing。窗口里一切互相竞争：每个 token 占掉其余 token 的份额。

**Session（会话）**：一段有边界的交互。从空开始累积消息/工具结果/读过的文件，结束于 clear、关闭或压缩成新会话。窗口是盒子，会话是慢慢装满盒子的东西。会话的消息史就是 agent 的工作记忆——模型无状态，它"记得"的一切都是每轮重发的消息史。

**Stateless / Stateful（无状态/有状态）**：模型跨请求永久无状态（参数推理后不更新，它不会从你的纠正里学习）；agent 跨会话默认无状态（新会话从零开始，昨晚熟读你代码库的 agent 今早一无所知）。记忆系统就是造状态的努力。

**Model provider request（模型请求）**：harness 发给模型服务商的一次调用。一个 turn 里有多次（每次工具结果回来都要再发一次完整窗口）。层级：session > turn > model provider request。

**Turn（轮）**：你的一条消息 + agent 到让回为止做的所有事。含一次或多次模型请求。轮的长度是 agent 的决定不是你的：你交出一条消息，它决定链多少个工具调用。一句回答或二十分钟读写都算一轮。

**Tool（工具）/ Tool call（工具调用）/ Tool result（工具结果）**：工具是 harness 给模型的命名能力（读文件、跑 bash）。工具调用是模型输出的结构化文本（工具名+参数 JSON）——它自己什么都不做，harness 解析、查权限、执行，把结果作为 tool result 塞回窗口。工具结果 是 agent 对环境的唯一视图。

**Environment（环境）**：agent 借工具感知与改变的世界——最常见是文件系统。AGENTS.md 住在环境里；harness 负责把它装进窗口。agent 只在看的时候才"看见"环境。

**MCP（Model Context Protocol）**：把外部工具服务器插进 harness 的协议——agent 获得 harness 出厂工具之外能力的标准方式。agent 从不"调用 MCP"，它调用工具，恰好那个工具来自某个 MCP server。

## 衰减与管理：为什么长会话变笨

**Attention budget（注意力预算）**：每个 token 能分给窗口其余部分的影响力是有限的。预算按 token 计、不随窗口变大。你的指令是固定音量的信号，其余每个 token 都是竞争的噪声——房间越满，信噪比越低。指令一个字没变，但越来越"听不见"。

**Smart zone（聪明区）**：会话早期模型敏锐专注；随会话增长漂进"笨区"：更马虎、更忘事、更多忠实性幻觉。前沿模型笨区常在 ~125K–150K token 开始。关键：**笨区不跟踪窗口上限**——质量在窗口远未满时就开始掉，没有报错没有边界，只是逐渐更糟（忘掉二十轮前的指令、重复已纠正的错误、自信地说出与上下文矛盾的话）。按 smart zone 规划任务，不按窗口上限；变笨的通常反应是"再解释一遍"——那加更多上下文，更糟。正确动作：clear 或 compact。

**Compaction（压缩）**：在内存里做的 handoff——把会话史摘要，用摘要种子一个新会话。设计上就有损：transcript 是一手来源，摘要二手。manual compact 发生在你选的阶段边界（可以告诉模型保什么）；**autocompact** 是 harness 在窗口快满（~80%）时自动触发的——有损且发生在你没选的时刻，可能在阶段中间劈断。摘要没留住的东西就从上下文里消失了。

**Clearing（清空）**：结束当前会话开新的——下一条消息从空会话空窗口开始。污染上下文的解药：会话积累了失败尝试、错误转弯、过期工具结果，模型每轮重读全部，坏历史拖累新工作。旧会话通常仍可恢复。

**Subagent（子代理）**：由另一个 agent 通过工具调用孵化、在自己的会话/窗口里跑、只回报一份结果的代理。与 handoff 的区别：父级期待回报。为**隔离上下文**而生，不是为层级——宽搜索/长阅读产生成页工具结果，在父级里跑全部留在父窗口，在子代理里跑噪声填一个可弃窗口，只有报告落回父级。报告是二手来源。

## 交接物：跨会话搬什么

**Handoff（交接）**：把 agent 上下文从一个会话转移到另一个。机制各异：写文档（handoff artifact）、内存摘要（compaction）。理由：换角色（规划→实现）、发起 AFK、并行扇出、腾窗口。接收会话从零开始——要带的东西必须显式写在载体里。

**Handoff artifact（交接物）**：一份被一个会话写进环境、被另一个会话读的文档。**spec、ticket、计划文档全是交接物**。它存在的理由：模型无状态，会话清了就什么都没了；环境持久，把重要状态写进文件就搬到下一个会话读得回的地方。交接物是二手来源——是会话的叙述不是会话本身。

**Spec（规格）**：描述一段多会话工作的交接物——建什么，不是每个会话怎么干它的份。会话可弃而大工程不可弃：超过一个窗口的功夫需要一个活在上下文之外的家（repo 里的文件、issue tracker）。

**Ticket（工单）**：框定**一个会话**工作量的交接物，可挂在 spec 下作为孩子。工单之间可互相阻塞，工作顺序从依赖图掉出来而不是线性计划。定义性约束是尺寸：一个 smart zone 内干得完。会话总在干完前变笨 → 票太大，拆。

**Primary / Secondary source（一手/二手来源）**：一手＝原形的真值：代码、对话 transcript、原始日志、真实 API 响应。二手＝对它的叙述：文档、架构图、摘要、README。agent 自信地说错你的项目时，先问它在哪个来源上工作。

**Memory system（记忆系统）**：试图让 agent 跨会话有状态的系统：写路径（会话中学到的偏好/事实落成环境里的文件）+ 读路径（会话开始时装回窗口）。

## 写作与披露：怎么喂 agent

**Context pointer（上下文指针）**：一份文档里指向另一份的提及，让 agent 只在任务需要时把它拉进窗口。progressive disclosure 的构建单元。用指针而不内联的理由是成本：指针一行，被指向的文档可能几千 token——不跟进就一文不花。把 2000 token 的 runbook 内联进 AGENTS.md，每个会话每轮都付；换成一行指针，只在真部署时付。

**Progressive disclosure（渐进披露）**：只加载当下需要的上下文，其余放在指针后面。存在理由：上下文是双重成本——每个预载 token 每轮付输入费，且不管用不用都花注意力预算。塞满风格指南+部署 runbook+数据库规范的 AGENTS.md 让 agent 每件事都变差。

## 工作模式：人与机器怎么配合

**Human-in-the-loop（人在环上）**：一个或多个人在会话中与 agent 配对——实时 review、纠偏、协作。意义：问题还便宜时抓住——看它伸手拿错文件、误读需求、走进死胡同，一句话拉回来，而不是二十分钟后收尸。

**AFK**：away from keyboard——踢一脚就走，agent 无人值守跑。AI coding 的吞吐放大器（多个 AFK 会话并行）。你不在时 agent 对歧义的处理不同：在场时歧义变成问题问你；离开后它选默认值继续跑，每个后来的歧义都再选一个。

**Vibe coding**：不看 diff 直接收代码的工作模式——diff 当黑盒，只看程序行为。Karpathy 2025 年初造词："完全交给感觉，忘了代码存在"。用检查换速度；一次性玩具可接受，要维护的工程是灾难。

**Permission mode（权限模式）**：哪些工具调用触发权限请求、哪些自动跑的门禁切片。典型梯度：只读（读自动/写挡）/ 默认（读自动/写与 shell 问）/ 自动编辑（编辑自动/shell 问）/ 全自动（配合沙箱）。DSH 对应：文件沙箱模式与审批策略（ask/never）。

**Sandbox（沙箱）**：agent 跑在里面的隔离环境（容器、VM、受限 shell）。限制爆炸半径：即使跑了破坏性命令，伤害被围住。与权限模式从两端解同一问题：权限在动作前问，沙箱在动作后限伤害。权限要你在环上，沙箱让 AFK 可行。

**Automated check / Automated review（自动检查/自动审查）**：程序性验证（测试、类型检查、lint）与 agent 对 diff 的结构化审查。自动检查是硬信号；automated review 是二手意见，进人审前的第一道。人的 review 管的是：这是不是*对的事*。

**Grilling（拷问）**：agent 苏格拉底式逐决策访谈用户、每题附推荐答案的技术。存在理由：agent 会**默默填空**——让它从两行提示写 spec，它不会停下来问没定的决策，它选默认值写进去，猜和选不可分辨。拷问把猜变成问。

**Prototyping（原型）**：让 agent 快速造个粗糙真物，用于对话分辨率不够的问题——交互手感、API 形状是否顺手、布局在真实数据量下行不行。访谈到"我得看一眼才知道"就该转原型。

## DSH 特有（实测补录）

**Profile（配置档）**：`~/.dsh/profiles/<name>` 下的有序插件束栈 + 你自己的 patch 层。`dsh web` / `dsh --profile headless` 是不同入口模式。

**Plugin（插件）**：带 `dsh.bundle` manifest 的 npm 包或本地 JS 模块，通过 profile 的 cordis.patch.yml 组合进运行时——可注册工具（ctx.tools）、技能（ctx.skills）等。

**Skill（技能）**：可复用的任务指令束，DSH 里是 `<name>/SKILL.md`（frontmatter: name/description/whenToUse + 可选 audience 控制）。默认只有 name+description 常驻上下文，任务匹配才加载正文——渐进披露的标准单元。来源根：项目 `.dsh/skills`、`~/.dsh/skills`、`~/.agents/skills`、运行时注册。

**Goal（目标）**：DSH 的长程机制：会话目标 + 自动续跑轮次，完成才 complete。把"跨多轮的活"交给它而不是一轮硬推。

## 补录词条（进阶）

**Agent mode（代理模式）**：塑造 agent 运行时行为的预设包＝权限模式 + 注入 system prompt 的行为指令。例：默认（危险调用弹窗）、plan mode（挡编辑、引导向研究）、自动编辑、绕过一切（YOLO）。会话中可切换。

**Permission request（权限请求）**：harness 执行未预批工具调用前给用户看的确认。批准→执行；拒绝→harness 把拒绝作为 tool result 回给模型。人在环上的机制本体。

**Input / Output tokens（输入/输出 token）**：输入＝每次请求发送的全部（system prompt+历史+工具结果），单价低，coding 账单的大头——模型无状态所以每轮重发整个会话；输出＝模型生成的一切（正文、代码、工具调用、**隐藏的推理 token 也按输出计费**），单价常约 5 倍。

**Cache tokens（缓存 token）**：prefix cache 命中的输入 token，低价。会话 append-only 所以命中率高——长会话付得起的杠杆。

**Model provider（模型服务商）**：为推理服务模型的一方——远端（Anthropic/OpenAI/Google）或本地（Ollama/LM Studio）。harness 自己跑不了模型，它向 provider 发 token 收预测。

**Attention degradation（注意力衰减）**：会话增长→每 token 的预算摊给更多竞争者→任一有意义关系上的信号缩小、无关噪声挤入。smart zone/dumb zone 效应的成因。表现：跟了一小时的约束开始溜号、重复已纠正的错误——同模型同参数，只是同一张嘴喂更多饭。

**Contextual knowledge（上下文知识）**：agent 此刻能从窗口直接读到的事实——你的任务、读进来的文件、工具结果、AGENTS.md。参数知识的对立面。基于上下文知识工作时幻觉大幅减少——答案就在眼前，不是从参数里捞的。事实性幻觉的解法：把正确知识装进来。

**Filesystem（文件系统）**：coding agent 的默认环境——文件目录树。AGENTS.md、技能、源码、构建脚本、工具配置都住里面。agent 只能通过工具调用摸它。

**Human review（人审）**：用户读 agent 产出的代码并形成判断。读 diff/改动文件算；**读 agent 对自己干了什么的叙述不算**——叙述是被审方写的二手来源，diff 才是一手。agent 放大代码产量，review 成为瓶颈。

**AX（agent experience）**：环境对 agent 做好活的友好程度，DX 的 agent 面对应物。同 agent 同 harness 在不同 repo 表现不同，变量常在 AX。直觉反应是怪模型或改 prompt，修法更多在 repo 里（可导航的结构、能跑的检查、写清的约定）。

**Design concept（设计概念）**：用户与 agent 共同持有的"在建什么"的共享理解，独立于任何资产（Brooks）。对话、交接物、代码都是试图捕捉它的资产，但都不是它本身。拷问磨练的就是它。
